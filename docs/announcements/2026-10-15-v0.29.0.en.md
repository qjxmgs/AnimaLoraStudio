Anima bases with different layer counts, including Anima-2.9B · LoRA / base layer-count checks · untagged images now train

### Added

- **Anima bases with different layer counts, including Anima-2.9B (#502, #504)**
  The layer count is now read from the weight file itself, so the 40-layer Anima-2.9B and similar extended variants train and generate normally. The Settings model catalog adds an Anima-2.9B preview-v1 download (about 5.8 GB), and base-model dropdowns, model path pickers, and the Settings main-model card show “N layers.”
  - Block swap for generation and the SRA layer for training no longer have a fixed upper limit; values above the base's actual layer count swap out every layer or use the last layer.
- **LoRA / base layer-count compatibility checks (#503, #504)**
  Newly trained LoRAs record the layer count of the base they were trained on. Generation rejects a LoRA that definitely doesn't match and warns about one that might not, such as an older or external LoRA without that record. The LoRA catalog on the Generate page shows each LoRA's training layer count and marks mismatches in red and possible mismatches in yellow.
  - Continuing training from an existing LoRA or resuming from a checkpoint now stops before training starts, with an explanation, when the base layer count differs from the original.

### Changed

- **Untagged images now take part in training (#599)**
  Only the training set's scan range decides which images train. Images without a caption file are no longer excluded; they train with empty text, so the same dataset may produce more samples and a higher step estimate. Tagging and tag editing also no longer require every image to be tagged before you can move on.
  - Clearing all tags in tag editing saves an empty caption instead of deleting the file. Missing and blank captions both show as “Untagged,” and tagging with “existing” set to Skip still tags them.
- **Base files with unrecognized DiT layer weights now fail to load (#502)**
  For example, ComfyUI `fp8_scaled` files with extra `blocks.*` keys used to load silently while producing incorrect training and generation results. They now stop with a message that the file doesn't match the model structure.

### Fixed

- **Third-party fine-tuned Anima bases failed to load with a `pos_embedder.seq` size mismatch (#502, #601)**
  These bases now load, train, and generate normally.
- **Downloaded custom base models were missing from the Train page and base-model dropdowns (#504)**
  They could previously be selected only in Settings for generation; they're now listed everywhere, like locally registered bases.
- **The axis-value delete button in the Generate page's XY grid jumped down when pressed (#598)**

### Upgrade notes

- This release has no required data migration. As usual, stop running jobs, close Studio, and back up `studio_data/` before updating.
- If your training set contains untagged images you don't want to train on, move them out of the training set before starting. See the [caption format guide (Chinese)](https://github.com/WalkingMeatAxolotl/AnimaLoraStudio/blob/master/docs/user-guide/caption-format.md) for the rules.
- LoRAs trained on 28-layer bases (Anima 1.0 and others) don't work with the 40-layer Anima-2.9B, and vice versa. Older LoRAs without a recorded layer count are checked by their weight key names and may show a yellow warning.
