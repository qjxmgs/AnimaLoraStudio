新模型族 MOSS-Image · Muon 与 Riemannion 优化器 · step 恢复点续训与不中断一致

### 新增

- **新模型族 MOSS-Image（#606、#607、#608、#609、#610、#611、#613、#616、#621、#627、#628）**
  训练页的模型族可以选 MOSS-Image（5B 单流 DiT，Qwen3.5-9B 文本编码器，FLUX.2 VAE）。训练 LoRA、训练中预览、测试页单图和 XY、先验生成、训练后评估都可以使用。设置页「训练」新增 MOSS-Image 模型分区，可下载 Base / SFT 主模型（bf16 / int8）、文本编码器（int8 / bf16）和 VAE。
  - 可以直接用 Comfy-Org 发布的 int8 ConvRot 量化底模训练和出图。int8 底模只支持 LoRA / LoKr / LoHa（不支持 DoRA），并且需要开启梯度检查点。
  - int8 底模出图按 ComfyUI 的计算方式进行，同参数下与 ComfyUI 的结果更接近；训练出的 LoRA 可以直接在 ComfyUI 中加载。
  - 测试页新增 Skip Layer Guidance 设置（跳过层、起始、结束），默认全程跳过第 22 层，与官方一致。
  - 支持 Block 交换（共 42 层）、显存策略、flash-attn / xformers 注意力后端，以及 NaViT 打包训练（文本 token 计入打包预算）。
- **Muon 优化器（#623）**
  训练页优化器新增 Muon，学习率可以沿用 AdamW 的设置；高级模式下可调动量、正交化迭代次数和学习率缩放方式。说明见[优化器文档](https://github.com/WalkingMeatAxolotl/AnimaLoraStudio/blob/master/docs/user-guide/optimizers.md)。
- **Riemann LoRA 适配器与 Riemannion 优化器（#624）**
  两者只能搭配使用：选择 Riemann LoRA 时优化器固定为 Riemannion，其他适配器下 Riemannion 不可选。保存的文件是普通 LoRA，测试页和 ComfyUI 可以直接加载，也可以从已有的普通 LoRA 继续训练。
  - Riemann LoRA 不使用 alpha、DoRA、rs-LoRA、dropout 和分层 rank，选中后这些字段会隐藏。

### 变更

- **从 epoch 中途的 step 恢复点续训，现在会跳过本 epoch 已训过的部分（#625）**
  以前会从该 epoch 开头重新训练，已训过的图片被重复训练，设了最大步数时 epoch 末尾的图片可能一直训不到。现在续训后的 loss 曲线与不中断训练一致。
  - 旧版本保存的恢复点没有记录 epoch 内进度，仍按原来的方式从 epoch 开头续训。
  - 开启 InfoNoise 时，同一 seed 的训练轨迹会与旧版本略有不同。
- **Anima 使用 er_sde 采样时，计算方式与 ComfyUI 对齐（#616）**
  同一 seed 的出图可能有极细微的差别。

### 改进

- **Anima / Krea 2 加载 int8 量化版底模或文本编码器时直接说明原因（#605）**
  这两个族不支持 ComfyUI 社区流行的 int8 量化权重（如 `*_int8_convrot`）。以前要等训练或出图启动后才报出含义不清的错误，现在加载时就提示改用同一模型的 bf16 或 fp8 版本；设置页和底模下拉里这类文件会标为「不可用」并禁选。
- **设置页的常驻说明文字收进 ⓘ（#622）**
  各 tab 的灰色说明段落移到对应标题或字段旁的 ⓘ 里；未下载的模型显示「未下载 · ~大小」。VAE、文本编码器、tokenizer 卡片与主模型卡片使用同样的样式。

### 修复

- **开启 Block 交换出图时，换出的层在某些情况下仍被整块搬上显存（#614、#615）**
  Krea 2 为文本编码器腾显存后、Anima 在 VAE 解码前后腾显存时会发生，Block 交换因此失效，小显存卡可能爆显存。Anima 开启 Block 交换时，VAE 解码前现在也会腾出常驻部分，减少被迫分块解码。
- **ⓘ 说明弹层在窄侧栏里被裁掉（#612）**
  另外在弹窗或抽屉里按 Esc 现在只关闭 ⓘ 弹层，不再连同外层一起关闭。
- **裁剪页「裁剪当前图」完成后，其他图还没提交的裁剪框被清空（#618）**
- **打标页 LLM 预设编辑器改完提示词消息后，滚动位置跳到顶部或底部（#620）**

### 升级提示

- 本版没有必须执行的数据迁移；照常停止运行中的任务、关闭 Studio，并在更新前备份 `studio_data/`。
- 依赖要求 transformers 升到 5.3 或更新版本（MOSS-Image 的文本编码器需要），并会连带升级 huggingface_hub、tokenizers 等依赖。通过 Studio 内自动更新升级时会自动安装，无需操作；手动 `git pull` 升级的话，请在 venv 中重新运行 `pip install -r requirements.txt`。
